# kickoff — 시작 10분

> **언제:** 과제 시작 직후, README를 내가 한 번 읽은 다음.
> **부르는 법:** Codex에게 `$kickoff` (안 되면 `.agents/skills/kickoff/SKILL.md 읽고 그대로 진행해줘`)
> **핵심:** 코드는 한 줄도 쓰지 않는다. 읽고 → 묻고 → 적는다.

---

## 에이전트가 할 일

### 1단계. 읽기
작업 폴더의 README와 과제 안내 파일을 읽는다.

### 2단계. 보고 (각 항목 3줄 이내)

```
## 지금 폴더에 있는 것 (코드 모르는 사람에게 설명하듯, 3줄)
- server.js: (뭘 하나)
- public/index.html: (뭘 보여주나)
- 그 외 눈에 띄는 것:

## 과제 요약
- 요청자: (누구 / 어떤 팀)
- 요청 한 줄: (README 표현 그대로)
- 제출물: (파일명·형식이 지정돼 있으면 그대로)

## README에 이미 적힌 것
- 확실한 요구사항:
- 제약 (기술·데이터·시간):

## README만으로 모르는 것 → 담당자에게 물을 질문
(사소한 것부터. 최대 7개. "할 일 목록 알려주세요" 류는 금지)
1. 지금은 이 일을 어떻게 하고 계세요?
2. 그 중에 제일 시간 많이 잡아먹는 단계가 뭐예요?
3. ...

## 위험 신호

- 180분 안에 못 할 것 같은 것:
```

### 3단계. PLAN 초안
사용자가 담당자 답변을 붙여넣으면 `docs/PLAN.md`의 1~6번을 채운 **초안**을 만든다.
- 성공 기준은 **확인 가능한 문장**으로. (좋은 예: "CSV 올리면 10초 안에 표로 보인다" / 나쁜 예: "편리하다")
- "만들 것"은 **3개 이하**, 우선순위 순
- "안 만들 것"에는 **담당자가 말했지만 이번엔 빼는 것**을 이유와 함께 적는다

### 4단계. 멈춤
초안을 사용자에게 보여주고 멈춘다. 사용자가 고친 뒤 담당자에게 확인받는다.

## 에이전트가 하지 않는 것
- 구현 시작
- 기술 방식 제안 (PLAN 확정 후에)
- 담당자가 말하지 않은 기능 추가

## 나(사용자)가 할 일
- 2단계 질문 목록을 보고 **내가 고른 순서로** 담당자에게 묻는다 (cheatsheet 2번 참고)
- 3단계 초안을 **내 말로** 고친다. 초안을 그대로 쓰지 않는다
