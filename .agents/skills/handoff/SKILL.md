# handoff — 인수인계 문서 쓰기

> **언제:** 11:30 (T+90), 12:45 (제출 직전). 약 3분씩.
> **부르는 법:** `$handoff` (안 되면 `.agents/skills/handoff/SKILL.md 읽고 진행해줘`)
> **왜 하나:** "다른 사람이 이어받을 수 있게 했는가"가 채점 항목(소통). 코파톤 Top 3가 이 문서로 점수를 땄음. 그리고 중간에 Codex 세션이 꼬여도 이 문서만 있으면 새 세션에서 이어갈 수 있음.

---

## 에이전트가 할 일

### 1단계. 현재 상태 확인 (파일을 다 다시 읽지 말고 필요한 부분만)
- `git log --oneline` → 지금까지 커밋 목록
- `docs/PLAN.md` → 성공 기준
- `docs/TEST_LOG.md` → 마지막 확인 결과
- `docs/DECISIONS.md` → 전체

### 2단계. `docs/HANDOFF.md`를 **처음부터 다시 쓴다** (덧붙이기 아님, 현재 상태 기준으로 새로)

| 항목 | 어떻게 쓰나 |
|---|---|
| 한 줄 요약 | 문제 + 만든 것 |
| 현재 상태 | 돌아가는 것 / 안 돌아가는 것. **TEST_LOG 기준으로만.** 추측 금지 |
| 구조 | 파일 3~5개와 역할. 더 있으면 덜 중요한 건 생략 |
| 핵심 결정 | DECISIONS.md에서 가장 중요한 3개 |
| 확인한 것 / 못 한 것 | TEST_LOG 그대로 |
| 남은 한계 | **솔직하게.** 숨기면 서술형에서 더 손해 |
| 다음에 할 일 | 우선순위 순 3개 이하 |

### 3단계. 커밋
`[docs] handoff T+___`

### 4단계. 한 줄 보고
"HANDOFF 갱신함. 남은 한계 N개."

## 에이전트가 하지 않는 것
- 코드 수정
- 한계를 좋게 포장하기
- 문서를 길게 쓰기 (한 화면 안에 들어와야 함)

## 나(사용자)가 할 일
- 12:45 버전은 **내가 직접 한 번 읽는다.** 서술형 6문제의 절반은 여기서 나온다고 보면 됨
- "남은 한계"에 적힌 것 → 서술형에서 "③ 약점" 답변 재료
