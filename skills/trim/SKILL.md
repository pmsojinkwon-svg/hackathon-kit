# trim

제출 20분 전에 쓴다. **제거 후보를 보고만 한다. 사용자가 고른 것만 지운다.**

## 할 일

1. `docs/PLAN.md`의 "만들 것"과 "안 만들 것"을 읽는다.
2. 코드 전체를 훑으며 아래에 해당하는 것을 찾는다.
   - PLAN의 "만들 것"에 없는 기능
   - "안 만들 것"에 있는데 들어간 것
   - 쓰이지 않는 함수·파일·변수
   - 요구사항보다 과한 방어: 사용자 1명인데 동시성 처리, 읽기만 하는데 쓰기 검증, 없을 입력에 대한 예외 처리
   - 설정 가능하게 만들었지만 설정할 일이 없는 것
   - 주석 처리된 죽은 코드
3. 아래 형식으로 보고한다.

```
## 제거 후보
| # | 위치 | 무엇 | 왜 과한가 | 지우면 생기는 위험 | 추천 |
|---|---|---|---|---|---|
| 1 | server.js:40-55 | 요청 속도 제한 | 사용자 1명, PLAN에 없음 | 없음 | 제거 |
| 2 | ... | | | | 유지 |

## 유지 추천 (과해 보이지만 이유가 있는 것)
- ...
```

4. 사용자가 번호를 고르면 **그것만** 지우고, 지운 뒤 `node server.js`로 서버가 켜지는지 확인한다.
5. 지운 내용을 `docs/DECISIONS.md`에 한 줄 추가한다: `(기능) 제거 | PLAN 범위 밖 | ... | 사용자`

## 하지 않는 것
- 보고 없이 지우기
- 지우는 김에 다른 부분 손보기
- 스타일·네이밍 지적 (이건 trim의 일이 아님)
