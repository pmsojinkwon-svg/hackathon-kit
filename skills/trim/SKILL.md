# trim — 과한 것 빼기

> **언제:** 제출 25분 전 (12:35).
> **부르는 법:** `skills/trim/SKILL.md 읽고 진행해줘`
> **핵심:** 제거 **후보를 보고만** 한다. 내가 고른 것만 지운다.
> **왜 하나:** 심사자가 "요구사항보다 과하게 만든 것"을 감점한다고 밝혔음. AI는 시키지 않은 것도 꼼꼼하게 만드는 버릇이 있어서, 마지막에 걷어내야 함.

---

## 에이전트가 할 일

### 1단계. 기준 읽기
`docs/PLAN.md`의 "만들 것"과 "안 만들 것"을 읽는다.

### 2단계. 찾기
코드 전체를 훑으며 아래에 해당하는 것을 찾는다.
- PLAN "만들 것"에 **없는** 기능
- "안 만들 것"에 있는데 들어간 것
- 쓰이지 않는 함수·파일·변수
- 요구보다 과한 방어: 사용자 1명인데 동시 접속 처리 / 읽기만 하는데 쓰기 검증 / 올 리 없는 입력에 대한 예외 처리
- 설정 가능하게 만들었지만 설정할 일이 없는 것
- 주석 처리된 죽은 코드

### 3단계. 보고

```
## 제거 후보
| # | 위치 | 무엇 | 왜 과한가 | 지우면 생기는 위험 | 추천 |
|---|---|---|---|---|---|
| 1 | server.js 40~55줄 | 요청 속도 제한 | 사용자 1명, PLAN에 없음 | 없음 | 제거 |
| 2 | ... | | | | 유지 |

## 유지 추천 (과해 보이지만 이유가 있는 것)
- ...
```

### 4단계. 지우기 (사용자가 번호를 고른 뒤)
- 고른 것**만** 지운다
- 지운 뒤 `node server.js`로 서버가 켜지는지 확인
- `docs/DECISIONS.md`에 한 줄: `(기능) 제거 | PLAN 범위 밖 | ... | 사용자`

---

## 에이전트가 하지 않는 것
- 보고 없이 지우기
- 지우는 김에 다른 부분 손보기
- 코드 스타일·이름 지적 (trim의 일이 아님)

## 나(사용자)가 할 일
- 표를 보고 **지울 번호를 고른다.** 애매하면 "유지"
- "유지 추천"에 있는 건 서술형에서 "왜 남겼나" 물어볼 수 있으니 이유를 기억해둔다
