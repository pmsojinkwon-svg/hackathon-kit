# verify

기능 하나 끝날 때마다, 그리고 제출 25분 전에 쓴다. **확인만 한다. 고치지 않는다.**

## 할 일

1. `docs/PLAN.md`의 "성공 기준"과 "확인 방법"을 읽는다.
2. 서버를 켠다: `node server.js` (이미 켜져 있으면 생략). 안 켜지면 여기서 멈추고 오류를 보고한다.
3. 성공 기준을 **하나씩** 실제로 확인한다.
   - 화면이면 `curl -s http://localhost:3000/` 로 HTML이 오는지, 핵심 문구가 들어있는지
   - API면 `curl -s http://localhost:3000/api/...` 로 응답 확인
   - 데이터 처리면 실제 입력을 넣고 출력 확인
4. 결과를 `docs/TEST_LOG.md`에 한 줄씩 추가한다. 형식: `시각 | 확인한 것 | 방법 | 결과`
   - 통과: `OK`
   - 실패: `FAIL - (무엇이 어떻게 다른지)`
   - 확인 못 함: `미확인 - (이유)`
5. 아래 형식으로 보고하고 멈춘다.

```
## 검증 결과
- 통과: N / 전체 M
- 실패:
  - (기준) → (현상) → (원인 추정, 확실하지 않으면 "추정")
- 미확인:
- 추천 다음 행동: (고칠 것 / 범위에서 뺄 것 / 그대로 제출)
```

## 하지 않는 것
- 실패를 발견해도 바로 고치지 않는다. 보고하고 사용자 결정을 기다린다.
- PLAN에 없는 것을 확인하지 않는다.
- 확인 안 한 것을 OK로 적지 않는다.
