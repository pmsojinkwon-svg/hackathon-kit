# verify — 확인만 한다

> **언제:** 기능 하나 끝날 때마다 + 제출 20분 전.
> **부르는 법:** `skills/verify/SKILL.md 읽고 진행해줘`
> **핵심:** 확인만. 실패를 발견해도 **고치지 않고 보고**한다. 고칠지는 내가 정한다.

---

## 에이전트가 할 일

### 1단계. 기준 읽기
`docs/PLAN.md`의 "성공 기준"과 "확인 방법"을 읽는다.

### 2단계. 서버 켜기
`node server.js` (이미 켜져 있으면 생략). 안 켜지면 **여기서 멈추고** 오류를 보고한다.

### 3단계. 하나씩 확인
성공 기준을 **한 개씩** 실제로 확인한다.
- 화면이면: `curl -s http://localhost:3000/` 로 HTML이 오는지, 핵심 문구가 들어있는지
- API면: `curl -s http://localhost:3000/api/...` 로 응답 확인
- 데이터 처리면: 실제 입력을 넣고 출력 확인

### 4단계. 기록
`docs/TEST_LOG.md`에 한 줄씩 추가. 형식: `시각 | 확인한 것 | 방법 | 결과`
- 통과 → `OK`
- 실패 → `FAIL - (무엇이 어떻게 다른지)`
- 못 함 → `미확인 - (이유)`

### 5단계. 보고하고 멈춤

```
## 검증 결과
- 통과: N / 전체 M
- 실패:
  - (기준) → (현상) → (원인 추정. 확실하지 않으면 "추정"이라고 씀)
- 미확인:
- 추천 다음 행동: (고칠 것 / 범위에서 뺄 것 / 그대로 제출)
```

---

## 에이전트가 하지 않는 것
- 실패를 발견해도 바로 고치기 (보고 → 사용자 결정 → 그때 고침)
- PLAN에 없는 것 확인하기
- 확인 안 한 것을 OK로 적기

## 나(사용자)가 할 일
- "추천 다음 행동"을 보고 **고칠지 / 뺄지 / 그냥 갈지** 결정한다
- 뺀다면 `docs/HANDOFF.md` "남은 한계"에 적게 시킨다
