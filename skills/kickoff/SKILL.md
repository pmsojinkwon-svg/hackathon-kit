# kickoff

과제 시작 후 첫 10분에 쓴다. **코드는 한 줄도 쓰지 않는다.**

## 할 일

1. 작업 폴더의 README와 과제 안내 파일을 읽는다.
2. 아래 형식으로 보고한다. 각 항목은 3줄 이내.

```
## 과제 요약
- 요청자: (누구 / 어떤 팀)
- 요청 한 줄: (README 표현 그대로)
- 제출물: (파일명·형식이 지정돼 있으면 그대로)

## README에 이미 적힌 것
- 확실한 요구사항:
- 제약 (기술·데이터·시간):

## README만으로 모르는 것 → 담당자에게 물을 질문
(사소한 것부터. 최대 7개. "할 일 목록 알려주세요" 류 금지)
1. 지금은 이 일을 어떻게 하고 계세요?
2. 그 중에 제일 시간 많이 잡아먹는 단계가 뭐예요?
3. ...

## 위험 신호
- 범위가 너무 넓어 보이는 지점:
- 180분 안에 못 할 것 같은 것:
```

3. 사용자가 담당자 답변을 가져오면 `docs/PLAN.md`의 1~6번을 채운 **초안**을 만든다.
   - 성공 기준은 "확인 가능한 문장"으로 (예: "CSV 올리면 10초 안에 표로 보인다")
   - "만들 것"은 3개 이하, 우선순위 순
   - "안 만들 것"에는 **담당자가 말했지만 이번엔 빼는 것**을 이유와 함께 적는다
4. 초안을 사용자에게 보여주고 멈춘다. 사용자가 고친 뒤 담당자 확인을 받는다.

## 하지 않는 것
- 구현 시작
- 기술 스택 제안 (PLAN 확정 후에)
- 담당자가 말하지 않은 기능 추가
