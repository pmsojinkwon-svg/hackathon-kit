# handoff

T+90, T+150, 제출 직전에 쓴다. 약 3분.

## 할 일

1. 아래를 확인한다 (파일을 다시 다 읽지 말고, 필요한 부분만).
   - `git log --oneline` 으로 지금까지 커밋
   - `docs/PLAN.md` 성공 기준
   - `docs/TEST_LOG.md` 마지막 결과
   - `docs/DECISIONS.md` 전체
2. `docs/HANDOFF.md`를 **전체 다시 쓴다** (덧붙이지 않고 현재 상태 기준으로 새로).
   - "한 줄 요약": 문제 + 만든 것
   - "현재 상태": 돌아가는 것 / 안 돌아가는 것을 TEST_LOG 기준으로. 추측 금지.
   - "구조": 파일 3~5개와 역할. 더 있으면 덜 중요한 건 생략.
   - "핵심 결정": DECISIONS.md에서 가장 중요한 3개
   - "확인한 것 / 못 한 것": TEST_LOG 그대로
   - "남은 한계": 솔직하게. 숨기면 나중에 더 손해.
   - "다음에 할 일": 우선순위 순 3개 이하
3. 커밋한다: `[docs] handoff T+___`
4. 사용자에게 "HANDOFF 갱신함. 남은 한계 N개." 한 줄만 보고한다.

## 하지 않는 것
- 코드 수정
- 한계를 좋게 포장하기
- 문서를 길게 쓰기 (한 화면 안에 들어와야 함)
