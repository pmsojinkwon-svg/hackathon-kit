# review

**새 터미널 탭에서 새 Codex 세션을 열고** 쓴다. 만든 세션이 자기 코드를 검토하면 의미가 없다.
제출 30분 전, 또는 큰 기능 하나 끝났을 때.

## 할 일

1. `docs/PLAN.md`를 읽고, 이 코드가 뭘 위해 만들어졌는지 파악한다.
2. 코드를 읽는다. 큰 파일은 핵심 부분만.
3. 아래 네 가지 질문에만 답한다. 각 3개 이하.

```
## 1. 돌아가나
- 서버 기동: (직접 켜봄 / OK / FAIL)
- PLAN의 성공 기준 중 코드상 구현이 안 보이는 것:

## 2. 어디서 깨지나 (장애 시나리오)
- (상황) → (무슨 일이 생기나) → (심각도: 높음/중간/낮음)
  예: 데이터 파일이 비어있을 때 → 화면이 빈 채로 멈춤 → 중간

## 3. 문서와 코드가 맞나
- DECISIONS.md에 적힌 것 중 코드와 다른 것:
- 코드에 있는데 DECISIONS.md에 없는 큰 선택:

## 4. 처음 보는 사람이 헷갈릴 곳
- (파일:줄) (왜)
```

4. 보고하고 멈춘다.

## 하지 않는 것
- 코드 수정
- 스타일·취향 지적
- "이렇게 했으면 더 좋았을 텐데" 류의 재설계 제안 (시간 없음)
- PLAN 밖 기능 제안
